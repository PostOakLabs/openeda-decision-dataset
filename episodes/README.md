# Episodes

An *episode* is one recorded engineering decision: the state before, what was
observed, what was considered and rejected, what was done, the state after, and
the judgment behind choosing it. The schema lives in
[PostOakLabs/engineering-decision-schema](https://github.com/PostOakLabs/engineering-decision-schema); this
directory is where the physical-design episodes go.

## The rule that governs this directory

**Nothing here may be invented.** Every number, every metric, every rationale
has to come from a run recorded by `flow/run.py` or from a person who was
there. A field that has not been filled in carries a `TODO(expert)` marker, and
`tools/check_episodes.py` fails the build while any marker remains.

That is stricter than it sounds, and deliberately so. A dataset of expert
judgment is worthless if a reader has to wonder which numbers were measured
and which were plausible-sounding.

## Layout

| Path | What it is |
|---|---|
| `templates/retrospective.template.json` | The canonical empty form. Copy it, or better, run `tools/new_episode.py`. |
| (this directory, top level) | Finished episodes, once there are any. |

## Working on an episode

```bash
# A blank retrospective episode, numbered automatically.
python tools/new_episode.py --design ibex --failure-class FAIL_TIMING \
    --out episodes/EP-IBEX-001.json

# An episode scaffolded from a run that actually happened. Everything the
# manifest knows -- RTL commit, PDK commit, tool versions, run id, and the
# metrics at two named stages -- is filled in for you.
python tools/new_episode.py \
    --from-run designs/ibex/runs/RUN_2026-08-28_12-00-00 \
    --prior-stage global_placement --post-stage detailed_routing \
    --failure-class FAIL_CONGESTION \
    --out episodes/EP-IBEX-002.json

# Check everything. Add --allow-draft while markers remain.
python tools/check_episodes.py
python tools/check_episodes.py --allow-draft
```

Prefer `--from-run` whenever a run exists. The fields it fills are the ones
most easily misremembered six months later, and it cannot fill them wrongly.

## Provenance

| Value | Meaning |
|---|---|
| `retrospective` | Recalled from a prior tapeout. No run artifact behind it. |
| `reproduced` | Regenerated by a committed flow run. Requires an `environment` block and pinned `rtl_commit` / `pdk_commit`. |
| `synthetic-fixture` | Validator food. **Not data.** Must live in a `fixtures/` directory. |

`retrospective` is not a lesser category. Most real decisions were made before
anyone thought to record them, and an honest recollection beats a fabricated
reproduction. It just has to be labelled as what it is.

## What a finished episode looks like

The two `candidates_considered` entries are the part people get wrong. Exactly
one must have `"rejected_because": null` — that one is the intervention that
was taken. The others carry the reason they were *not* taken. An episode with
only the winning option recorded is a log entry, not a decision: the rejected
alternatives are where the judgment actually lives.
